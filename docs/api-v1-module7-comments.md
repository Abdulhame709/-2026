# Module 7 — تعليقات الفروق (قرارات المالك: الجميع يعلّق + تُطبع في التقرير)

التاريخ: 2026-09-06 · الالتزامات السابقة: `0e43a1f` (M6) ثم إصلاحات اختبار المالك.

## المبدأ
«دفتر ملاحظات مثبّت بجانب كل فرق» — الفريق يوثّق there ماذا اتفق مع المورد ولماذا قُبل فرق،
والملاحظات تخرج في تقرير الجلسة المطبوع تحت كل فرق (ذاكرة مؤسسية لا تضيع).

## الجدول
`discrepancy_comments` — موجود منذ المخطط الأولي (001)، بلا تغيير:
`id, discrepancy_id→discrepancies CASCADE, author_id→users, comment text, created_at`.
ترحيل `003_module7_comments.sql`: فهرس `(discrepancy_id, id)` للترتيب الزمني فقط.

## نقاط النهاية (كلها تحت /api/v1)
| المسار | الطرف | الصلاحية | الغرض |
|---|---|---|---|
| `GET  /discrepancies/{id}/comments` | الجميع | قراءة تعليقات فرق (الأقدم أولاً) |
| `POST  /discrepancies/{id}/comments` | **الجميع حتى العارض** (قرار المالك) | إضافة ملاحظة — النص إجباري 1..2000 حرف بعد التنقية |
| `GET   /discrepancies/session/{sid}/comments` | الجميع | ملاحظات كل فروق جلسة — لتقرير الجلسة (نداء واحد) |
| `DELETE /discrepancies/comments/{cid}` | صاحب الملاحظة أو مدير (403 لغيرهما) | حذف ملاحظة |

الردود بنمط النظام الموحد `{ ... }` / `{ error: { code, messageAr, details?, traceId } }`.
أخطاء الحقول تفصّل على الشاشة تلقائياً (آلية userMessage من إصلاح «السحب لا يقبل»).

## التدقيق
`DISCREPANCY_COMMENT_ADD` (after: commentId+body) و`DISCREPANCY_COMMENT_DELETE`
(before: commentId) — entity_type=discrepancy، مع IP الفاعل.

## الواجهة
- **لوحة تفاصيل الفرق** (Drawer): قسم «ملاحظات الفريق (العدد)» — الكل يقرأ ويضيف؛
  زر حذف يظهر لصاحب الملاحظة أو المدير (مع Popconfirm). الكاتب + دوره (مدير/محاسب/مُطالع) + الوقت.
- **تقرير الجلسة**: تحت كل فرق صف رمادي فاتح بملاحظاته «الكاتب (التاريخ): النص» — يُطبع مع التقرير
  ويدخل في PDF المتصفح، وسيُلتقط تلقائياً في PDF الخلفي القادم (M10).

## حدود مقصودة (حفاظاً على البساطة)
لا تعديل لنص ملاحظة بعد نشرها (تحذف وتُعاد كتابتها) — التعديل يفسد التوثيق الزمني.
