# API — الوحدة 3: استيراد الكشوفات (Statements)

> قاعدة المسار: `/api/v1` · المصادقة: كوكي httpOnly `recon_session`؛ Bearer اختياري عند `ISSUE_BEARER_TOKEN=on`؛ لا يُقبل `?sid=`.
> الكتابة (رفع/تصحيح/اعتماد/يدوي): أدمن أو مُطابِق فقط. القراءة: الجميع.
> المغلف الموحد للخطأ: `{error:{code,messageAr,traceId,details?}}`.

## الفلسفة (من تحليل stage-2b)

1. **النص الخام هو المرجع في المعاينة** — التواريخ والمبالغ تُعرض وتُصحَّح كما استُخرجت
   (`dateRaw`/`debitRaw`/`creditRaw`)، والتحويل الرقمي/التاريخي يحدث مرة واحدة عند الاعتماد
   بمحقق صارم (Q11: صفر تسامح مالي).
2. **المعاينة في ذاكرة الخادم** (توكن 24 حرفاً، عمر 30 دقيقة) — لا يُكتب شيء في القاعدة
   قبل الاعتماد. إعادة تشغيل الخادم تُبطل المعاينات (مقبول: FR-3.3 معاينة قبل الحفظ).
3. **Excel/CSV** عبر مكتبة xlsx، وPDF/الصور عبر استخراج محلي ثم معاينة خادمية بتوكن؛
   يبقى `POST /statements/manual` للإدخال اليدوي بلا ملف.
4. **القالب اختياري عند الرفع** — بلا `templateId` يفحص الخادم ترويسة الملف ويتعرّف على
   الأعمدة (تاريخ/نوع/رقم/بيان/مرجع/مدين/دائن/مبلغ/رصيد/عملة) بدل افتراض A–E، والواجهة
   تعرض التعيين للمراجعة قبل الرفع (`POST /statements/inspect`)؛ ويمكن حفظ التعيين كقالب
   لنفس نوع الملف. عند اختيار `templateId` يُستخدم القالب المحفوظ مباشرة.
5. **اكتشاف أرصدة الترويسة**: أول صف تاريخه غير قابل للتحليل وفيه كلمة «رصيد» ومبلغ
   → رصيد افتتاحي؛ وأي صف مشابه لاحق → ختامي مرشّح (`closingHint`).

## المسارات

### POST /statements/inspect — فحص الأعمدة واقتراح التعيين (multipart/form-data)

| الحقل | النوع | ملاحظات |
|---|---|---|
| `file` | ملف | .xlsx/.xls/.csv حتى 15MB — لا كتابة في القاعدة |
| `accountId` | رقم | للتحقق من الحساب النشط |
| `side` | `ours\|theirs` | يحدد اتجاه الاستنتاج لاحقاً |

**201**: `{inspection:{sheetName, sheetNames, headerRowIndex, headerRows, columns:[{index,letter,header,sample,field}], mapping, decimalSep, thousandSep, warnings}}`
- `mapping` يقترح حرف العمود لكل حقل (`date/docType/docNo/description/ref/debit/credit/amount/balance/currency`).
- `warnings` تفسّر الافتراضات: عمود «الرصيد» يُعامل كمبلغ، عمود العملة يُهمل، واتجاه المبلغ الواحد.
- التعرّف يطابق ترويسات عربية/إنجليزية، ويكمل الناقص بفحص المحتوى (تواريخ/مبالغ/نصوص).

### POST /statements/upload — رفع ومعاينة (multipart/form-data)

| الحقل | النوع | ملاحظات |
|---|---|---|
| `file` | ملف | .xlsx/.xls/.csv حتى 15MB — PDF = 422 برسالة تأجيل صريحة |
| `accountId` | رقم | حساب مورد نشط (Q11: الحساب مربوط بعملة) |
| `side` | `ours\|theirs` | كشفنا (أونكس) / كشفهم |
| `templateId` | رقم/فارغ | اختياري — عند اختياره يُستخدم القالب المحفوظ مباشرة |
| `mapping` | JSON | اختياري — خريطة مؤكدة من الواجهة `{date:'A', description:'C', amount:'F'}` |
| `headerRows` | رقم | اختياري — عدد صفوف الترويسة (افتراضي 1) |
| `decimalSep` / `thousandSep` | `.`/`,` | اختياري — فواصل التحليل المكتشفة |
| `saveTemplate` | JSON | اختياري — `{name, isDefault}` يحفظ التعيين كقالب للجهة/الحساب |

**201**: `{token, lines:[{lineNo,dateRaw,docType,docNo,description,ref,debitRaw,creditRaw}], opening, closingHint, templateId, lineCount, sheetName, decimalSep, thousandSep, mapping}`
- بلا `mapping`/`templateId`: تعرّف تلقائي على الأعمدة من الملف نفسه، وإن فشل يظهر خطأ صريح
  بدل استيراد أعمدة خاطئة.
- إعدادات التحليل (`dateFormats/decimalSep/thousandSep`) تُخزَّن مع المعاينة، ويقرأها الاعتماد
  منها — لا من القالب فقط.
- يُحفظ الملف فوراً في `backend/storage/uploads` مع sha256؛ يُسجَّل في `source_files` عند الاعتماد فقط.
- الأخطاء: `VALIDATION_FAILED` (بنود `field:'file'` لأسباب النوع/الحجم، و`field:'mapping'` لخريطة ناقصة أو مكررة).

### PUT /statements/preview/{token}/lines/{lineNo} — تصحيح بند معاينة

الجسم: أي مجموعة من `{dateRaw, description, debitRaw, creditRaw, ref, docType, docNo}` (نصية).
**200**: `{line}` — **410 `PREVIEW_EXPIRED`** إن انتهت صلاحية المعاينة.

### POST /statements/preview/{token}/commit — الاعتماد النهائي

الجسم (كله اختياري): `{openingBalance?, announcedClosing?, announcedCount?, sessionId?}`. ينطبق المسار على معاينات Excel/CSV وPDF/الصور؛ يُربط الأصل بالكشف عند الاعتماد.

**محقق الاعتماد (Q11)** — يفشل الاعتماد كلياً بأول خرق، بتفاصيل لكل بند:
1. كل بند: تاريخ قابل للتحليل + بيان غير فارغ + مدين أو دائن على الأقل (يجوز الاثنان)، ولا مبلغ سالب.
2. `announcedClosing` إن ورد: |المحسوب − المعلن| ≥ 0.00005 → رفض برسالة تُظهر الرقمين.
   المحسوب حسب الجهة (stage-2b §2.3): كشفهم = افتتاحي + Σمدين − Σدائن،
   وكشفنا = افتتاحي + Σدائن − Σمدين (أونكس: رصيد المورد دائن) — أي: افتتاحي + Σ الموقَّع.
3. `announcedCount` إن ورد ويختلف عن عدد البنود → رفض.

**201**: `{statementId, lineCount, totalDebit, totalCredit, sessionId?, bothAttached?}`
- الكتابة: معاملة واحدة — `source_files` + `statements` (status `committed` مباشرة،
  فترة الكشف min/max تواريخ البنود، opening/closing) + `statement_lines`.
- `signed_amount`: كشفنا = دائن − مدين، كشفهم = مدين − دائن.
- `extracted_refs`: كل الأرقام 2–6 خانات من البيان+المرجع (dedup) — لتقاطع المطابقة (Module 4).
- تحذير `findOverlapping` يُسجل في سجل الخادم عند تقاطع فترة مع كشف معتمد سابق (نفس الحساب/الجهة/العملة).
- التدقيق: `STATEMENT_COMMIT`.

### POST /statements/manual — إدخال يدوي (بلا ملف)

`{accountId, side, sessionId?, openingBalance?, lines:[{entryDate, description, ref?, debit?, credit?}]}`
- نفس محقق البنود؛ لا يقبل بيانات ثقة OCR أو ملفاً أصلياً. لاستيراد PDF/صورة مع أصل قابل للتدقيق، استخدم مسار المعاينة المرتبط بتوكن.
- **201**: `{statementId, lineCount, totalDebit, totalCredit, sessionId?, bothAttached?}` — تدقيق `STATEMENT_MANUAL`.

### GET /statements/{id} — تفصيل كشف ببنوده (الجميع)

**200**: `{statement:{…, opening_balance, closing_balance, period_start, period_end, status}, lines:[…]}`

## قرارات مسجّلة

- **صرامة التواريخ**: YYYY يقتضي 4 أرقام؛ السنة القصيرة (26→2026) تُقبل فقط في تمريرة
  متساهلة ثانية، وتُقدَّم فيها صيغ «يوم-أولاً» (DD/MM) على «السنة-أولاً» — `30-06-26`
  = 2026-06-30 وليس 2030-06-26. الشهور/الأيام تُدقق (<1990 مرفوض).
- **تنظيف المبالغ**: يُسقط ضوضاء العملة (YER/USD/SAR/ر.ي/﷼/$) وفواصل الآلاف قبل التحويل.
- **سطر الافتتاحي داخل الجدول** (بتاريخ صالح) يبقى بنداً عادياً — لا يُستخرج رصيداً؛
  الاستخراج مخصص لصفوف الترويسة بلا تاريخ.
- الخلايا تُقرأ من الأعمدة المعيّنة بالقالب المحفوظ أو المؤكدة في الواجهة؛ وبلا تعيين
  يتعرّف الخادم على الترويسات العربية/الإنجليزية الشائعة (تاريخ/بيان/مدين/دائن/مرجع…)
  ثم يكمل الناقص بفحص المحتوى. الأفضل حفظ القالب بعد أول تعيين ناجح.
- **مبلغ واحد مقابل مدين/دائن**: إن غاب عمودا مدين/دائن ووُجد «المبلغ» (أو «الرصيد» عند
  غيابه) تُستنتج الجهة من الإشارة وجهة الكشف: الموجب دائن في «كشفنا» ومدين في «كشف المورد»،
  والسالب عكس ذلك؛ والواجهة تعرض تحذيراً صريحاً قبل الاعتماد.
- **عمود العملة** يُكتشف ويُهمل عمداً — المطابقة تجري بعملة حساب المورد، مع تحذير.
- **CSV يُقرأ نصاً خاماً** (`raw: true`) فلا تحوّل مكتبة xlsx القيم إلى أرقام تفقد الفواصل
  الأصلية؛ تبقى الأرقام العربية وفواصل الآلاف/العشرية كما في الملف للتصحيح والتحليل.

## الواجهة (المعالج)

`StatementUploadStep` متصل بالخادم: رفع فعلي (FormData + قنوات الجلسة الثلاث)،
قوالب الحساب حقيقية (خيار «تلقائي» دائماً)، تصحيح كل خلية يُحفظ في المعاينة الخادمية
(فشل الشبكة يعيد النص السابق)، حقلا «ختامي/عدد معلن» اختياريان في محقق التوثيق،
والاعتماد يستدعي commit ويعرض رقم الكشف. `StepCreateSession` يعرض الموردين الحقيقيين
ويحسب `accountId` من (الطرف + العملة). تبقى عرضية: قائمة الجلسات القائمة (تعارض) وسجل
الجلسات — Module 4/6.
