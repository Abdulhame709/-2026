# ضوابط النشر والنسخ الاحتياطي — قبل فتح النظام للشبكة

## حالة التنفيذ

- الواجهة التطويرية والخادم يستمعان على `127.0.0.1` فقط افتراضياً؛ هذه حماية من التعريض العرضي وليست HTTPS.
- `TRUST_PROXY=loopback` اختياري لوكيل عكسي على **نفس الجهاز** فقط. اتركه غير مفعّل أثناء التشغيل المحلي المباشر؛ لا تثق بترويسات `X-Forwarded-*` القادمة من المتصفح.
- تنشئ النسخة الجديدة (الإصدار 2) ملف `.enc` واحداً مشفراً بــ AES-256-GCM يجمع جداول PostgreSQL وملفات `backend/storage/uploads` (الكشوف والشعارات)، مع بصمة SHA-256 لكل ملف. تنسخ بحد أقصى 256 ميغابايت و2000 ملف؛ عند فقد ملف مرجعي أو اختلاف بصمته أو تجاوز الحد تُرفض العملية بلا إنشاء نسخة ناقصة. النسخ لا تشمل جلسات الدخول.
- تتحقق الاستعادة من التشفير وبنية الملف وبصمات الملفات **قبل** تعديل القاعدة. تكتب ملفات النسخة بأسماء جديدة داخل مجلد الرفع قبل معاملة قاعدة البيانات، ثم تعيد توجيه سجلات `source_files` والشعار إليها؛ لا تمس الملفات القديمة، لتجنب ضياعها إن فشلت الاستعادة. تُنظَّف الملفات الجديدة عند فشل المعاملة قبل محاولة COMMIT، وقد تبقى ملفات إضافية عند فشل غير مؤكد أثناء COMMIT؛ افحصها يدوياً ولا تحذفها عشوائياً.
- النسخ القديمة (الإصدار 1، ولو شُفّرت لاحقاً) تحتوي الجداول فقط. لا تُستعاد إلا إذا كانت ملفات الكشوف المشار إليها موجودة محلياً وبصماتها مطابقة، وكان الشعار موجوداً؛ التحويل من JSON إلى `.enc` **لا يضيف** الملفات المرفوعة. الملف القديم الموجود في `backend/storage/backups` بصيغة `.json` **لا يزال غير مشفّر** وقد يتضمن بيانات حساسة؛ لم نعدله أو نحذفه.
- فحص البيئة الحالية لم يثبت وجود شهادة لاسم وصول عبر LAN؛ شهادة `localhost` تخص هذا الجهاز ولا تؤمّن اسماً آخر. خدمة IIS تعمل لكن فحص إعدادات الموقع لم ينجح بالصلاحيات المتاحة؛ لم نغيّر ربط IIS أو المنافذ أو تشغيل الموقع.

## متطلبات إتاحة النظام على شبكة داخلية

1. قدّم الواجهة المجمّعة (`frontend/dist`) عبر IIS أو وكيل عكسي مع شهادة TLS صالحة، واجعل `/api` يمر إلى الخادم المحلي `127.0.0.1:3000`. لا تُقدّم خادم تطوير Vite للمستخدمين ولا تفتح منفذ الخادم أو PostgreSQL للشبكة.
2. اجعل الوكيل يزيل ترويسات `Forwarded` و`X-Forwarded-*` الواردة من العملاء ويعيد ضبط `X-Forwarded-Proto` و`X-Forwarded-For` بنفسه، ثم فعّل `TRUST_PROXY=loopback` للخادم عند الحاجة. احصر الاتصال بالخادم المحلي ولا تستخدم قيمة الثقة العامة `true`.
3. أغلق HTTP الخارجي أو حوّله إلى HTTPS قبل إرسال أي بيانات دخول؛ اختبر الدخول عبر HTTPS ووجود `Secure` و`HttpOnly` و`SameSite` على الكوكي، ثم جرّب رفع ملف وتنزيل تقرير ورفض طلب تغيير بــ `Origin` أجنبي. لا يُعد الاستماع المحلي ضماناً لتشفير الطريق بين المتصفح والوكيل.
4. وفّر مفتاحاً عشوائياً مستقلاً بطول 32 بايت (64 رمزاً سداسياً) في `BACKUP_ENCRYPTION_KEY` لحساب خدمة الخادم عبر مدير أسرار موثوق **خارج المستودع ومجلد النسخ**. للاستخدام المحلي بحساب Windows الحالي، انظر `docs/BACKUP-KEY-SETUP.md` لسكربت إعداد محمي بـDPAPI ومشغّل يحمّل المفتاح للخادم دون عرضه. لا تُدرجه في ملفات المشروع أو سجل الأوامر أو الرسائل. احفظ وسيلة استعادته بشكل آمن خارج الجهاز؛ إذا فُقد فلن يمكن فك النسخ، وإذا تغير فلن تُقرأ النسخ القديمة. لا تُنشأ نسخ جديدة بلا مفتاح صالح؛ سيظهر خطأ `BACKUP_KEY_REQUIRED` بدلاً من كتابة JSON نصي.
5. قيد صلاحيات `backend/storage/backups` و`backend/storage/uploads` على حساب خدمة التطبيق والمدير فقط. بعد إعداد المفتاح، أنشئ **نسخة جديدة شاملة** وتحقق منها خارج جهاز العمل. يمكن تشفير JSON القديم دون حذف الأصل، لكن ذلك لا يجعله نسخة شاملة؛ قيّد الوصول إليه حتى تتخذ قراراً آمناً بشأنه.
6. اختبار الاستعادة الآلي `npm run test:backup-restore` ينشئ قاعدة PostgreSQL مؤقتة وملفات **اصطناعية**، ويختبر استعادة القاعدة والكشوف والشعار، ونقلها إلى مسار جديد، ورفض العبث والملفات المفقودة، وعدم عودة الجلسات، ثم يحذف قاعدة الاختبار ومجلداته. نجح محلياً، ولا يُعوض بروفة استعادة نسخة عمل فعلية في بيئة معزولة ولا مراجعة حسابات قديمة مُعادة.
7. عند تعذر قراءة ملف مشفر يظهر في القائمة بوصفه «تعذر التحقق» مع تعطيل الاستعادة؛ قد يكون المفتاح خاطئاً أو الملف تالفاً. غياب المفتاح يمنع عرض القائمة المشفرة بخطأ `BACKUP_KEY_REQUIRED`، فلا تعتبر غياب العرض دليلاً على خلو المجلد.

**تحديث 2026-11-15:** أُعد مفتاح محلي محمي بحساب Windows، وأفاد المالك بحفظ نسخة منه خارج الجهاز. أنشئت نسخة حقيقية شاملة وتأكدنا من فكها وأربع ملفاتها، ونجحت استعادتها على قاعدة ومجلد مؤقتين حُذفا بعد الاختبار. **لم تُمس قاعدة العمل بالاسترجاع.** ملف JSON القديم غير المشفر باقٍ، وأذونات مجلدي النسخ والرفع لا تزال تحتاج تشديداً مدروساً. HTTPS مؤجل ما دام الموقع على هذا الجهاز فقط. حذف الملفات المؤقتة لا يعني محواً جنائياً لآثارها من القرص؛ يُفضل تشفير قرص الجهاز عند استخدام بيانات عمل حساسة.
