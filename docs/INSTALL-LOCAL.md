## خطوات التثبيت (PowerShell)

### 1) تنزيل الكود
```powershell
git clone -b arena/01a0735f-2026 https://github.com/Abdulhame709/-2026.git
cd -2026
```
> بعد دمج الفرع في `main` سيكفي: `git clone https://github.com/Abdulhame709/-2026.git`

### 2) إنشاء قاعدة البيانات
افتح **pgAdmin** (يأتي مع مثبّت PostgreSQL) أو psql ونفّذ:
```sql
CREATE DATABASE reconciliation;
```

### 3) تجهيز الخادم (backend)
```powershell
cd backend
npm install
# كلمة مرور القاعدة التي اخترتها أثناء تثبيت PostgreSQL:
$env:PGPASSWORD = "كلمة_المرور_هنا"
npm run db:migrate   # إنشاء الجداول (5 ملفات هجرة)
$env:NODE_ENV = 'development'
# عيّن SEED_ADMIN_PASSWORD وSEED_RECONCILER_PASSWORD وSEED_VIEWER_PASSWORD بكلمات فريدة من 12 حرفاً على الأقل عبر بيئة آمنة قبل الخطوة التالية
npm run db:seed      # بيانات تطوير فقط؛ المستخدمون الجدد ملزمون بتغيير كلمات المرور
```

### 4) تشغيل الخادم
```powershell
npm run dev
# ✓ الخادم يعمل على http://localhost:3000
```

### 5) تشغيل الواجهة (نافذة PowerShell ثانية)
```powershell
cd frontend
npm install
npm run dev
```
ثم افتح المتصفح: **http://127.0.0.1:5173**

### 6) أول دخول
استخدم `admin` أو `reconciler` أو `viewer` بكلمات المرور الفريدة التي عيّنتها عند زرع بيانات التطوير. سيُطلب تغييرها قبل متابعة العمل. لا تشغّل البذور في الإنتاج، وغيّر أي كلمات قديمة مُستخدمة فعلياً وأبطل جلساتها.

## ملاحظات مهمة

1. **لا تحتاج سكربت `db:bootstrap` على ويندوز** — هو مخصص لبيئة التطوير (لينكس) التي تنزّل PostgreSQL مضمّناً. على جهازك، PostgreSQL المثبت هو القاعدة.
2. **إعدادات الاتصال** قابلة للضبط بمتغيرات البيئة إن خالفت الافتراضيات:
   `PGHOST` (الافتراضي 127.0.0.1) · `PGPORT` (5432) · `PGUSER` (postgres) · `PGDATABASE` (reconciliation) · `PGPASSWORD` (من البيئة).
3. **النسخ الاحتياطي** يحتاج مفتاحاً عشوائياً بطول 32 بايت، ولا يعمل بدونه. لإعداده مرة واحدة على Windows **دون وضعه في المستودع** اتبع `docs/BACKUP-KEY-SETUP.md`؛ المشغّل `s.bat` يستخدم الملف المحلي المحمي بعد إعادة تشغيل الخادم. النسخ الجديدة تجمع القاعدة والملفات المرفوعة حتى 256 ميغابايت في ملف مشفر واحد. احتفظ بملف النسخة والمفتاح خارج الجهاز؛ لا تستعد النسخ القديمة قبل مراجعة الحسابات والملفات التي قد تعيدها.
4. **الترقية لاحقاً**: `git pull` ثم أعد `npm install` في المجلدين إن تغيّرت التبعيات، ثم `npm run db:migrate` إن وصلت هجرات جديدة.
5. للتشغيل على الجهاز نفسه استخدم `npm run dev`؛ خادما التطوير والخلفية يستمعان على `127.0.0.1` فقط. قبل إتاحة النظام لأي جهاز آخر، شغّل الواجهة المجمّعة خلف HTTPS ولا تفتح Vite أو API مباشرة على الشبكة؛ انظر `docs/DEPLOYMENT-SECURITY.md`.
