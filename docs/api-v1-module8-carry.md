# Module 8 — الترحيل الآلي للرصيد الافتتاحي (D9 — قرار المالك: سبب التعديل إجباري)

التاريخ: 2026-09-06 · يعتمد: جلسات مغلقة ببنود موثقة (صفر تسامح — لا أرقام معلنة).

## المبدأ (بلغة العمل)
عند إنشاء جلسة جديدة لأي حساب، يسأل النظام: «ما آخر جلسة مغلقة لهذا الحساب؟» فيجلب **ختاميها
المحسوب من بنودها** ويملأ الافتتاحيين (عندنا/عندهم) تلقائياً مع بيان المصدر. أي تعديل يدوي
على المرحَّل يوجب **سببًا (≥5 أحرف)** يُخزَّن ويُدقَّق ويُطبع في التقرير — توثيق كامل بلا استثناء.

## معادلة الختامي (نفس معادلة التحقق في الاعتماد)
- ختامنا = COALESCE(افتتاحي الجلسة، افتتاحي كشفنا، 0) + Σدائن − Σمدين (بنودنا)
- ختامهم = COALESCE(افتتاحي الجلسة، افتتاحي كشفهم، 0) + Σمدين − Σدائن (بنودهم)

لا اقتراح إن لم تكن للجلسة المغلقة بنود (لا نرحّل أصفاراً زائفة) — سلوك مهم لجلسات المالك 8/9.

## نقاط النهاية
| المسار | الغرض |
|---|---|
| `GET /sessions/opening-suggestion?accountId=N` | `{ suggestion: { fromSessionId, periodLabel, closedAt, closingOurs, closingTheirs } \| null }` |
| `POST /sessions` | حقول جديدة: `openingTheirs?`, `carriedFromSessionId?`, `openingAdjustReason?` |

## التحقق الخادمي الصارم (لا ثقة بالعميل)
`carriedFromSessionId` مُرسل ⟸ يجب أن تكون الجلسة مغلقة ولنفس الحساب وبنود موثقة، وإلا 422
برسالة عربية واضحة. ثم يُعاد حساب الختاميين خادمياً: أي اختلاف (>0.005) بين المرسل والمحسوب
— أو تفريغ حقل كان سيُرحَّل بقيمة غير صفرية — يوجب `openingAdjustReason` ≥5 أحرف وإلا 422:
«عدّلت الرصيد المرحَّل يدوياً — سبب التعديل إجباري…».

## التخزين والتدقيق والتقرير
- أعمدة `reconciliation_sessions`: `carried_from_session_id` (من المخطط الأولي) + `opening_adjust_reason`
  (ترحيل `004_module8_carry.sql`).
- التدقيق: `SESSION_CREATE` يوثق `{ carriedFrom, adjusted, adjustReason }`.
- تفصيل الجلسة يعرض `carriedFromSessionId/carriedFromPeriod/openingAdjustReason`.
- تقرير الجلسة: سطر تحت جدول الأرصدة — «الرصيد الافتتاحي مرحَّل آلياً من جلسة {فترة} المغلقة —
  متصل بآخر إقفال موثق» أو «… — عُدِّل يدوياً والسبب: …».

## الواجهة (المعالج — الخطوة 1)
- عند اختيار المورد والعملة: جلب الاقتراح وملء الحقلين آلياً + تنبيه نجاح بالمصدر والقيمتين.
- أي تعديل يظهر حقل «سبب تعديل المرحَّل (إجباري)» ويمنع «التالي» حتى 5 أحرف (تحقق مزدوج مع الخادم).
- تبديل الحساب يصفّر المرحَّل والحالة اليدوية (لا قيم قديمة من حساب آخر).

## اختبار مُنفَّذ (حساب رمي ثم حُذف)
سلسلة كاملة: لا اقتراح قبل الإغلاق → رفض ترحيل عبر حسابات → كشفان بفتتاحي 1000 وحركة 400 →
إغلاق → اقتراح 1400/1400 → جلسة مرحَّلة 201 → تعديل بلا سبب 422 → مع سبب 201 + السبب في القاعدة
والتدقيق → التفصيل يعرض المصدر والفترة.
