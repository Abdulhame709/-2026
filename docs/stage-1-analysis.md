## 1. الغرض ونطاق الوثيقة

تحدد هذه الوثيقة **ماذا** سيفعل النظام (وليس **كيف** يُبنى تقنياً). تشمل: المتطلبات الوظيفية مقسمة لوحدات، المتطلبات غير الوظيفية، الأدوار والصلاحيات، حالات الاستخدام الأساسية، الافتراضات، والأسئلة المفتوحة.

### 1.1 المصطلحات (Glossary)

| المصطلح | المعنى |
|---|---|
| **كشف الطرف الآخر** | الكشف الوارد من المورد/العميل من نظامه هو (Excel/PDF/ممسوح) |
| **كشف الشركة** | الكشف الصادر من ERP الشركة لنفس الحساب |
| **جلسة مطابقة (Reconciliation Session)** | عملية مطابقة واحدة: حساب معين + عملة معينة + فترة معينة + النسختان + النتائج |
| **بند (Line/Entry)** | سطر واحد في كشف: فاتورة، دفعة، خصم، مرتجع... |
| **فرق (Discrepancy)** | بند لا يوجد له مقابل مطابق تماماً، أو يوجد مقابل باختلاف |
| **البند المجمّع** | فاتورة واحدة عندنا تجمع عدة فواتير عنده (أرقامها في البيان) — Q10 |
| **دفعة تحت الحساب** | دفعة بلا ربط بفواتير محددة — Q10 |
| **خريطة المراجع** | جدول يربط رقم الفاتورة اليدوي عندنا برقمها الآلي عند المورد — Q8 |
| **رمز السبب** | تصنيف موحد لسبب الفرق (خصم، مرتجع، دفعة غير مسجلة...) — Q9 |

### الوحدة 4: محرك المطابقة (Matching Engine) — قلب النظام

> **قاعدة حاكمة من Q11: لا يوجد أي هامش تسامح مالي.** التطابق في المبلغ يجب أن يكون تاماً 100%، وأي فرق ولو وحدة واحدة = فرق يظهر مع بيان سببه.

| # | المتطلب |
|---|---------|
| FR-4.1 | مطابقة تلقائية متدرجة القواعد (بترتيب قابل للضبط لكل طرف):<br>**المرحلة أ:** مرجع تام — رقم الفاتورة عندنا = رقمها عنده (بعد توحيد الصياغة: إزالة أصفار بادئة/رموز)<br>**المرحلة ب:** مرجع من **خريطة المراجع** (رقمنا اليدوي ↔ رقمه الآلي) (FR-2.5)<br>**المرحلة ج:** مرجع **مستخرج من البيان** — استخراج الأرقام المرجعية من نص البيان ومطابقتها (يغطي "أرقام الفواتير مكتوبة في البيان" — Q8/Q10)<br>**المرحلة د:** بدون مرجع — مبلغ تام + تاريخ داخل نافذة الطرف (استبعاد المطابقات المستهلكة) |
| FR-4.2 | دعم **1:1** (بند مقابل بند) و **1:N / N:1** (البند المجمع عندنا = عدة فواتير عنده — Q10) |
| FR-4.3 | **مطابقة المبلغ المجمّع**: مجموع عدة بنود عنده = مبلغ البند المجمع عندنا، مع مراجعة البنود المكونة له |
| FR-4.4 | **اقتراح توزيع "دفعة تحت الحساب"**: اقتراح الفواتير المفتوحة التي تغطيها الدفعة (قيمةً وتاريخاً) ليؤكدها المحاسب — اقتراح فقط، القرار يدوي (R3) |
| FR-4.5 | **مطابقة يدوية كاملة**: ربط أي بنود يدوياً (1:1 أو 1:N) وفك أي ربط آلي — مع تسجيل من فعلها ومتى |
| FR-4.6 | كل نتيجة مطابقة تحمل **درجة ثقة ومصدر القاعدة** الذي طابقتها (شفافية كاملة: لماذا طُوبق هذا البند؟) |
| FR-4.7 | تصنيف آلي للنتائج: **مطابق تماماً / مطابق بفروق (مبلغ أو تاريخ أو مرجع) / بند عندنا فقط / بند عنده فقط** |
| FR-4.8 | إعادة تشغيل المطابقة بعد أي تعديل يدوي دون فقدان القرارات اليدوية السابقة |
| FR-4.9 | عدم قبول مطابقة غير متوازنة مالياً (المبالغ يجب أن تتساوى تماماً في كل ربط) — قاعدة Q11 |
| FR-4.10 | فصل كامل بين العملات — لا مطابقة عبر عملات (Q11) |

| # | المتطلب |
|---|---------|

## 5. حالات الاستخدام الأساسية (Top 5 Core Use Cases)

### UC-01: إنشاء جلسة مطابقة واستيراد الكشوفات
- **الفاعل:** محاسب مطابِق
- **الهدف:** تجهيز جلسة مطابقة شهرية لحساب مورد بعملة محددة بعدد الكشوفات
- **الخطوات:**
  1. يفتح "جلسات المطابقة" ← "جلسة جديدة"
  2. يختار: الطرف (مورد X) + العملة + الفترة (شهر 8/2026)
  3. يرفع كشف الشركة (تصدير ERP) ← يختار قالب الأعمدة المحفوظ ← معاينة ← اعتماد
  4. يرفع كشف الطرف الآخر ← اختيار القالب (أو إنشاء قالب جديد لأول مرة) ← معاينة وتصحيح أي استخراج خاطئ ← اعتماد
  5. النظام يشغّل المطابقة التلقائية ويعرض لوحة النتائج
- **المسارات البديلة/الأخطاء:**
  - **أ1:** أول تعامل مع هذا المورد — لا قالب: يربط الأعمدة يدوياً ويحفظ القالب (FR-2.3)
  - **أ2:** فشل استخراج PDF: يُحوّل النظام لوضع المعاينة مع تمييز المشكلة؛ وإن كان الملف ممسوحاً → مسار UC-05
  - **هـ1:** مبلغ غير رقمي/تاريخ غير مفهوم: يُعلَّم الصف ولا يُحفظ الكشف حتى يُصحح (FR-3.4)
  - **هـ2:** رفع ملف بعملة مختلفة عن الجلسة: يُرفض مع رسالة واضحة (FR-4.10)
  - **هـ3:** رفع نفس الملف مرتين: يُنذر بالتكرار (مطابقة بصمة الملف)

### UC-02: مراجعة نتائج المطابقة الآلية والتعديل اليدوي
- **الفاعل:** محاسب مطابِق
- **الهدف:** الوصول لنتيجة مطابقة صحيحة 100% مراجعةً وربطاً يدوياً حيث فشلت الأتمتة
- **الخطوات:**
  1. يعرض النظام النتائج مصنفة: مطابق / بفروق / عندنا فقط / عنده فقط — مع مصدر قاعدة كل مطابقة (FR-4.6)
  2. يراجع عينة من المطابقات الآلية، ويفكّ أي ربط خاطئ
  3. يختار بنوداً غير مطابقة ← "ربط يدوي" ← يحدد البند المقابل عنده (أو عدة بنود للبند المجمع — FR-4.2/4.3)
  4. لدفعة تحت الحساب: يعرض النظام اقتراح التوزيع على الفواتير ← يؤكد أو يعدّل (FR-4.4)
  5. عند اكتشاف ارتباط مرجعي جديد (رقم يدوي ↔ رقم آلي) يقترح النظام حفظه في خريطة المراجع ← يوافق (FR-2.5)
  6. يعيد تشغيل المطابقة ويكرر حتى نفاد المستقل المحلول
- **المسارات البديلة/الأخطاء:**
  - **هـ1:** محاولة ربط بمبالغ غير متساوية: يُرفض — المطابقة اليدوية تشترط التوازن التام (FR-4.9)
  - **هـ2:** ربط بند استُهلك في ربط سابق: يُمنع مع إظهار ربطه الحالي
  - **أ1:** لا يوجد مقابل أصلاً → يصنف البند فرقاً (UC-03)

### UC-03: تسجيل الفروق ومتابعتها حتى الحل
- **الفاعل:** محاسب مطابِق
- **الهدف:** كل فرق له سبب موثق ومسؤول وحالة حتى يُحل فعلياً
- **الخطوات:**
  1. يفتح فرقاً من قائمة الفروق (مثال Q9: فاتورتنا 9,500 وفاتورته 10,000)
  2. يحدد رمز السبب: "خصم مُبلَّغ لم يُطبَّق عنده" ويربطه بسجل التسويات المبلَّغة إن وجد (FR-5.3)
  3. يعيّن مسؤولاً ويكتب ملاحظة المتابعة ← الحالة "قيد المتابعة"
  4. بعد رد المورد/التصحيح: يوثّق الحل ← "محلول" أو "مقبول" مع بيان الأثر المالي
  5. الفروق غير المحلولة نهاية الجلسة تُرحَّل تلقائياً لجلسة الشهر التالي (FR-5.7)
- **المسارات البديلة/الأخطاء:**
  - **هـ1:** محاولة إغلاق الجلسة وفروق مفتوحة بلا تصنيف: يُمنع الإغلاق (FR-5.6)
  - **أ1:** اتضح أن الفرق خطأ عندنا: يصحح في ERP خارج النظام ويوثّق هنا "محلول — صُحح في النظام المحاسبي" (الأداة لا تعدل في ERP — خارج النطاق)

### UC-04: إصدار تقرير المطابقة وأرشفته وإرساله
- **الفاعل:** محاسب مطابِق (المطالعة يستعرض فقط)
- **الهدف:** تقرير رسمي قابل للطباعة يُرسل للمورد ويُحفظ في الأرشيف
- **الخطوات:**
  1. بعد اكتمال المراجعة يغلق الجلسة (بشرط لا فروق مفتوحة بلا تصنيف)
  2. "إنشاء التقرير" ← يعرض المعاينة: ترويسة + ملخص + تفصيل + الفروق وأسبابها
  3. يصدّر PDF (للمورد) وExcel (للداخل) (FR-6.2)
  4. يرفق خطاب المطابقة ليعتمد المورد الرصيد أو يعلّق (FR-6.6)
  5. يُحفظ التقرير في أرشيف الحساب مع تاريخه (FR-6.4) وتُسجل عملية التصدير في التدقيق
- **المسارات البديلة/الأخطاء:**
  - **أ1:** المورد أرسل لاحقاً كشفاً مصححاً: يُعاد فتح الجلسة (صلاحية Admin — انظر المصفوفة) ويُرفع الكشف الجديد وتُعاد المطابقة، ويُحفظ إصدار تقرير جديد
  - **هـ1:** جلسة غير مغلقة: لا يُسمح بإصدار "تقرير نهائي" — يُتاح "مسودة تقرير" فقط

### UC-05: استيعاب كشف ممسوح ضوئياً (Paper-to-Data)
- **الفاعل:** محاسب مطابِق
- **الهدف:** إدخال كشف ورد صورة/مسحاً ضوئياً بدقة موثوقة رغم منع الخدمات السحابية (Q5 + Q16)
- **الخطوات (قرار D5 — المساران متاحان معاً):**
  1. يرفع الصورة/الملف الممسوح
  2. يختار: **OCR محلي** (بلا إنترنت) يستخرج مسودة البنود، أو **الإدخال اليدوي المدعوم** مباشرة
  3. في مسار OCR: تفتح **شاشة تدقيق مقترنة** — الصورة على جهة والبنود المستخرجة على الجهة الأخرى صف بصف، والأرقام المالية تُراجع كلها إلزامياً (لا اعتماد أعمى للـ OCR)
  4. في المسار اليدوي: شبكة إدخال سريعة بجانب الصورة المعروضة (إضافة سطر، نقل القيم، تنقل بلوحة المفاتيح)
  5. اعتماد ← يكمل كأي كشف مستورد (UC-01)
- **المسارات البديلة/الأخطاء:**
  - **أ1:** جودة الصورة تجعل OCR مضللاً: التحويل الفوري لمسار الإدخال اليدوي المدعوم بنقرة واحدة مع بقاء الصورة معروضة
  - **هـ1:** فشل التعرف على اتجاه الصورة/اللغة: طلب صورة أوضح أو التحويل للإدخال اليدوي
  - **قاعدة:** أي بند لم يُراجعه بشرياً لا يدخل المطابقة أبداً
