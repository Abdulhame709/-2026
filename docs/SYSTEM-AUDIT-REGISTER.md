# سجل الفحص الشامل — صفحة صفحة وتبويب تبويب

> بدأ 2026-11-28 بطلب المالك: فحص كل أكواد النظام لاستكشاف أخطاء قراءة الملفات
> وتصحيحها وإضافة الميزات الاحترافية. هذا السجل هو الخريطة الحيّة: ما فُحص، وما
> أُصلح، وما بقي، حتى لا يُدّعى فحص لم يحدث.

## طريقة العمل

1. كل وحدة تُفحص في فرع مستقل، مع اختبارات آلية قبل طلب الدمج.
2. «فُحص» تعني: قراءة الشيفرة + تشغيل مسارها الفعلي أو اختبارها آلياً + إصلاح
   ما ظهر. لا تعني «يعمل عند المالك على بياناته».
3. لا تُمس قاعدة بيانات العمل أثناء الفحص؛ اختبارات التكامل تنشئ قواعد مؤقتة.
4. كل بند «متبقٍ» يحتاج عينة حقيقية منزوعة الحساسية أو قرار مالك (نشر، بيانات).

## الوحدة 1 — قراءة ملفات الكشوفات (2026-11-28) ✅

### ما كان يفسد القراءة فعلياً

| العطل | الأثر على المستخدم | الإصلاح |
|---|---|---|
| مبالغ سالبة بصيغة `(1,234.50)` أو `1,234.50-` أو `−` | تُرفض كغير رقمية أو تُقرأ موجبة | `parseAmount` يفهم أقواس المحاسبة والسالب اللاحق وكل إشارات النص |
| عملات موسّعة (SAR/AED/OMR/KWD/درهم/دينار) | تبقى حروفاً فتفشل الخلية | تنظيف عملات أوسع قبل التحليل |
| CSV بترميز Windows-1256 (تصدير Excel العربي) | رفض الملف أو عربية مشوهة | محاولة UTF-8 ثم UTF-16 ثم Windows-1256 |
| CSV بفاصل `;` أو Tab أو سطر `sep=;` | أعمدة ملتصقة/إزاحة كاملة | كشف الفاصل من أول خمسة أسطر ودعم `sep=` |
| تاريخ مع وقت `2026-01-31 10:20` أو `T10:20:00Z` | تاريخ غير صالح → اعتماد ممنوع | نزع الوقت واسم اليوم قبل التحليل |
| تاريخ Excel التسلسلي و`YYYYMMDD` | خلايا فارغة/تواريخ 1970 | دعم التسلسلي (UTC) والرقم المضغوط |
| أسماء الشهور: `31 يناير 2026` / `Jan 31, 2026` | تاريخ غير مفهوم | تحليل أسماء الشهور العربية والإنجليزية |
| غموض `04/05/2026` (يوم/شهر أم شهر/يوم) | تواريخ معكوسة بصمت | كشف الترتيب من القيم + اختيار صيغة التاريخ في الواجهة |
| ترويسة على صفين/خلايا مدمجة | صف الترويسة الفرعي يصبح بنداً | امتداد الترويسة تلقائياً وأخذ أدق اسم عمود |
| صفوف الترويسة المكررة داخل الجدول | بنود وهمية بمبالغ غير رقمية | كشفها بكلمات الأعمدة وتخطّيها مع عدّها |
| صفوف «الإجمالي/المجموع/رصيد افتتاحي/ختامي» | تُحسب كحركات فتفسد المطابقة | فصلها: الافتتاحي/الختامي يُقترحان، والباقي يُتخطّى |
| عمود «الرصيد» فقط | يُعامل كحركة بلا تنبيه كافٍ | يبقى سلوكاً معتمداً مع تحذير صريح في لوحة التعيين |
| «رقم/له/عليه/مدين-دائن» في الترويسات | أعمدة غير معروفة | مرادفات أوسع، و`مدين/دائن` المجمّع → مبلغ |
| ورقة خاطئة في مصنف متعدد الأوراق | رفض أو قراءة ورقة الغلاف | اختيار الورقة من الواجهة وتمريرها للفحص والتحليل |

### ما أُضيف احترافياً

- **اختيار صيغة التاريخ** من لوحة التعيين (ست صيغ) مع اكتشاف تلقائي للترتيب،
  وتُحفظ مع القالب وتُستخدم عند الاعتماد.
- **اختيار ورقة الملف** من نفس اللوحة عند وجود أكثر من ورقة، دون إعادة رفع.
- **عدّاد الصفوف المتخطّاة** يظهر بعد التحليل: «تُخطّي N صف ترويسة/رصيد/إجمالي»
  حتى لا يظن المستخدم أن بنوداً ضاعت.
- **الافتتاحي والختامي المقترحان** من صفوف الكشف نفسها، مع عدم خلط «الإجمالي»
  بالرصيد الختامي الصريح.
- **توحيد محقق الواجهة مع الخادم**: نفس قواعد التاريخ والمبلغ والسالب، فلا يمر
  بند في الواجهة ويفشل عند الاعتماد (أو العكس).
- **قراءة الصيغ الغريبة بأمان**: فاصل عشري معكوس يُستنتج عند فشل إعدادات القالب،
  بدل رفض المبلغ.

### الاختبارات

- `backend/tests/import-reading.test.mjs`: من 11 إلى **17** اختباراً، تشمل:
  السالب المحاسبي، العملات، الفواصل المعكوسة، الوقت/التسلسلي/YYYYMMDD/أسماء

  الافتتاحي/الإجمالي/الختامي، الترويسة ذات الصفين، واختيار ورقة صريحة.
- `backend/tests/statements-http.integration.mjs`: يتحقق من `dateFormats` و
  `sheetName` و`ignoredRows` عبر HTTP ثم الحفظ والاعتماد.
- `npm run typecheck` و`npm run build` و`test:statements-http` و`test:stage3` ناجحة.

### حدود هذه الوحدة

- عينات العمل الحقيقية (ملفات الموردين الفعلية) لم تُرفع للمستودع، والاختبارات
  اصطناعية تحاكي الأنماط الشائعة. أي نمط جديد يحتاج عينة منزوعة الحساسية.
- ملفات PDF ذات تخطيط بصري غير قياسي تبقى ضمن مسار OCR ومراجعته الإلزامية.
- قوالب محفوظة قديمة قد تحمل `dateFormats` ناقصة؛ تُستكمل بالصيغ الافتراضية.

## الوحدة 2 — إعادة بناء جداول PDF من الإحداثيات (2026-11-28) ✅

### ما كان يفسد القراءة فعلياً

| العطل | الأثر على المستخدم | الإصلاح |
|---|---|---|
| الاعتماد على ترتيب مقاطع pdfjs بدل موضعها (x/y) | أعمدة الرصيد/رقم المستند/التاريخ تُقرأ كمبالغ، وبنود بلا مبالغ | بناء شبكة صفوف بصرية من الإحداثيات ثم أعمدة حقيقية |
| حروف عربية تقديمية (NFKC) وأرقام هندية وعلامات اتجاه وتطويل | ترويسات لا تُطابق المرادفات وأرقام لا تُحلَّل | `normalizePdfText` قبل كل شيء |
| نص عربي قصير يُحاذى ليمين خليته | ينزاح إلى عمود التاريخ المجاور | إعادة إسناد بحدّ اليمين الوسيط لكل عمود (مقاوم للشين) |
| ترويسة مجموعة «المبلغ» فوق «دائن/مدين» | عمود وهمي يسرق قيم أحد الجانبين | إسقاط رأس المجموعة الأب عند وجود فرعين فعليين |
| تاريخ مقسوم بين سطرين («2025-01-» + «01») | بند بلا تاريخ أو تاريخ ناقص | دمج الأجزاء داخل عمود التاريخ |
| أسطر وصف مكمّلة بلا تاريخ | تُقطع كتذييل أو تُحسب بنوداً وهمية | دمجها في البند السابق، مع حماية صفوف الافتتاحي/الختامي |
| تذييل الكشف (مجاميع/مسحوبات/توقيع/طباعة) | مبالغ وهمية تضخّم المجاميع | قطع كل ما يلي آخر صف مؤرّخ |
| عمود كمية/قيمة بضاعة بجانب مدين/دائن | يُحسب كحركة إضافية | إهمال amount/balance عند وجود مدين/دائن صريحين |
| «تدوير أرصدة» وصفوف الافتتاحي | تُحسب حركة وتضاعف الرصيد | تُقرأ رصيداً افتتاحياً لا بنداً |
| ختامي بلا صف صريح | لا يُقترح رصيد ختامي | آخر رصيد جارٍ في العمود يُستخدم كاقتراح ختامي |

### آلية العمل

1. `extractPdfWords` + `groupPdfRows`: تجميع المقاطع في صفوف بصرية بتسامح 3–7 نقاط.
2. `detectLayout`: تعلّم الأعمدة من صف/صفّي الترويسة عبر `matchHeader`، وإسقاط
   أعمدة المجموعات بلا بيانات.
3. الإسناد الأولي بالمركز، ثم ضبط RTL بحدّ اليمين الوسيط، ثم بناء الخلية حسب
   نوعها (تاريخ/رقم/نص) بترتيب قراءة عربي.
4. `mergeSplitDates` و`mergeContinuationRows` ثم قطع التذييل بعد آخر تاريخ.
5. تمرير الشبكة إلى `detectColumnMapping` ثم `parseStatementRows` — نفس قواعد
   Excel/CSV حرفياً (افتتاحي/ختامي/مجاميع/جهة الكشف)، بلا مسار تحليل موازٍ.
6. صفحات التكملة بلا ترويسة تعيد استخدام تخطيط الصفحة السابقة (`priorLayout`).

## الوحدة 3 — تحصين Excel/CSV (2026-11-28) ✅

### ما أُصلح

| الحالة | الأثر قبل الإصلاح | الإصلاح |
|---|---|---|
| CSV بنهايات أسطر `\r` وحدها (تصدير قديم) | الملف كله يُقرأ سطراً واحداً | تقسيم `\r\n|\r|\n` |
| CSV بفاصل `|` | أعمدة ملتصقة/إزاحة | إضافة `|` إلى مرشحي الفاصل |
| سطر `sep=\t` مكتوباً حرفياً | لا يُفهم ويُقرأ كعمود واحد | دعم `sep=\t` و`sep=<حرف>` |
| UTF-16 بلا BOM | عربية مشوهة أو رفض | كشف توزّع البايتات الصفرية واختيار LE/BE |
| ورقة مخفية فيها معاملات | «معاملات في عدة أوراق» توقف الاختيار التلقائي | تُستبعد الورقة المخفية ما دامت هناك ورقة ظاهرة |
| نطاق منسّق إلى مئات آلاف الصفوف | استهلاك ذاكرة كبير أو تعليق | سقف 200,000 صف × 1,000 عمود + `sheetRows` أثناء القراءة |
| مصنف بلا أوراق | رسالة عامة | رسالة عربية صريحة |

### الاختبارات

- أُضيفت **4** اختبارات في `backend/tests/import-reading.test.mjs` (CR/`|`/`sep=\t`،
  UTF-16 بلا BOM، رفض النطاق الضخم، تفضيل الورقة الظاهرة)، فصار المجموع **26**.
- `test:import` و`test:stage3` و`test:backup` ناجحة مع `typecheck` و`build`.

### حدود

- السقف 200,000 صف يكفي كشوفات سنوات طويلة؛ الملفات الأكبر تحتاج تقسيمها أو رفع السقف بقرار مالك.
- CSV غير القياسي (فواصل غير مذكورة أو حقول متعددة الأسطر بلا اقتباس) يبقى خارج الضمان.
