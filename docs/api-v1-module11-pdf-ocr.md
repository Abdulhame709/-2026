# Module 11 — استيراد كشوف PDF محلياً (OCR) — قرار المالك وQ16

التاريخ: 2026-09-06 · **كل شيء محلي 100%: بلا أي خدمة سحابية أو API خارجي.**

## المبدأ
أفلت ملف PDF في نافذة رفع الكشف → يستخرج النظام البنود محلياً → **مسودة مراجعة إلزامية** في
نفس جدول المعاينة (كل بند قابل للتصحيح) → الاعتماد عبر مسار الإدخال اليدوي بعد المراجعة.
«القراءة الآلية قد تخطئ» — قرار التوثيق: لا يدخل رقم للقاعدة دون عين مراجع.

## المساران (كلاهما داخل الخادم)
1. **طبقة نصية**: استخراج مباشر عبر pdfjs-dist — تحليل أعمدة عام مستقل عن اتجاه المقاطع
   (بعض المولدات كي pdfkit تكتب الأسطر بترتيب بصري): خلية الوصف = الأكثر حروفاً عربية،
   والتاريخ من أي خلية، والمال من بقية الخلايا. سطرا «رصيد منقول/افتتاحي» و«ختامي» يُكتشفان
   كأرصدة ولا يُدرجان بندين.
2. **ممسوح (صور)**: تصيير الصفحات ≈200dpi محلياً (pdfjs + @napi-rs/canvas) ثم Tesseract
   مضمّن النظام بنموذجي `ara+eng` (الحزم محلية من npm، تُنسخ إلى storage/tessdata أول مرة).
   ثقة القراءة تُسجَّل مع كل بند (ocr_confidence) وتظهر الحاجة للمراجعة.

## نقاط النهاية
| المسار | الغرض |
|---|---|
| `POST /statements/ocr` | ملف PDF → `{ draft: { pages, mode: 'text'\|'ocr', opening, lines[] } }` — مسودة فقط |
| `POST /statements/manual` | الاعتماد بعد المراجعة (نفس مسار الإدخال اليدوي المعتمد) — البنود مع `ocrConfidence` |

## الواجهة
- نافذة الرفع تقبل الآن `.pdf`: رسالة info بعد الاستخراج بعدد البنود وتحذير المراجعة،
  وجدول المعاينة نفسه قابل للتصحيح، وزر الاعتماد يمر عبر المسار اليدوي.
- Excel/CSV يبقيان على مسار القوالب والمعاينة الخادمية كما هما (لا تغيير).

## حدود معلومة (شفافية)
- ترتيب الكلمات داخل وصف البند قد يأتي بترتيب بصري في بعض ملفات الطبقة النصية، وقد يلزم
  نقل مبلغ بين عمودي مدين/دائن — كلاهما تصحيحه بنقرة في المراجعة الإلزامية.
- الملفات الممسوحة بجودة رديئة تعطي ثقة منخفضة — يُنصح 200dpi فأعلى.
