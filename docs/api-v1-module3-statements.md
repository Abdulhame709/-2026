# API — الوحدة 3: استيراد الكشوفات (Statements)

> قاعدة المسار: `/api/v1` · المصادقة: كوكي httpOnly `sid` + Bearer + `?sid=` (قنوات الجلسة الثلاث).
> الكتابة (رفع/تصحيح/اعتماد/يدوي): أدمن أو مُطابِق فقط. القراءة: الجميع.
> المغلف الموحد للخطأ: `{error:{code,messageAr,traceId,details?}}`.

## الفلسفة (من تحليل stage-2b)

1. **النص الخام هو المرجع في المعاينة** — التواريخ والمبالغ تُعرض وتُصحَّح كما استُخرجت
   (`dateRaw`/`debitRaw`/`creditRaw`)، والتحويل الرقمي/التاريخي يحدث مرة واحدة عند الاعتماد
   بمحقق صارم (Q11: صفر تسامح مالي).
2. **المعاينة في ذاكرة الخادم** (توكن 24 حرفاً، عمر 30 دقيقة) — لا يُكتب شيء في القاعدة
   قبل الاعتماد. إعادة تشغيل الخادم تُبطل المعاينات (مقبول: FR-3.3 معاينة قبل الحفظ).
3. **Excel/CSV الآن** (مكتبة xlsx) — PDF يُرفض برسالة عربية صريحة (الرقمي عبر PdfPig
   والممسوح عبر OCR: خطوة لاحقة من الخطة المعتمدة). الإدخال اليدوي/OCR متاح عبر
   `POST /statements/manual` (بعد التدقيق البشري، حقول ثقة OCR اختيارية).
4. **القالب اختياري عند الرفع** — بلا `templateId` يُستخدم قالب الحساب الافتراضي
   (نوع الجهة)، وإلا القالب التلقائي A–E (تاريخ/مرجع/بيان/مدين/دائن، ترويسة سطر واحد).
5. **اكتشاف أرصدة الترويسة**: أول صف تاريخه غير قابل للتحليل وفيه كلمة «رصيد» ومبلغ
   → رصيد افتتاحي؛ وأي صف مشابه لاحق → ختامي مرشّح (`closingHint`).

## المسارات

### POST /statements/upload — رفع ومعاينة (multipart/form-data)

| الحقل | النوع | ملاحظات |
|---|---|---|
| `file` | ملف | .xlsx/.xls/.csv حتى 15MB — PDF = 422 برسالة تأجيل صريحة |
| `accountId` | رقم | حساب مورد نشط (Q11: الحساب مربوط بعملة) |
| `side` | `ours\|theirs` | كشفنا (أونكس) / كشفهم |
| `templateId` | رقم/فارغ | اختياري — الافتراضي تلقائياً |

**201**: `{token, lines:[{lineNo,dateRaw,docType,docNo,description,ref,debitRaw,creditRaw}], opening, closingHint, templateId, lineCount}`
- يُحفظ الملف فوراً في `backend/storage/uploads` مع sha256؛ يُسجَّل في `source_files` عند الاعتماد فقط.
- الأخطاء: `VALIDATION_FAILED` (بنود `field:'file'` لأسباب النوع/الحجم).

### PUT /statements/preview/{token}/lines/{lineNo} — تصحيح بند معاينة

الجسم: أي مجموعة من `{dateRaw, description, debitRaw, creditRaw, ref, docType, docNo}` (نصية).
**200**: `{line}` — **410 `PREVIEW_EXPIRED`** إن انتهت صلاحية المعاينة.

### POST /statements/preview/{token}/commit — الاعتماد النهائي

الجسم (كله اختياري): `{openingBalance?, announcedClosing?, announcedCount?}`

**محقق الاعتماد (Q11)** — يفشل الاعتماد كلياً بأول خرق، بتفاصيل لكل بند:
1. كل بند: تاريخ قابل للتحليل + بيان غير فارغ + مدين أو دائن (ليس الاثنين، ليس سالباً).
2. `announcedClosing` إن ورد: |المحسوب − المعلن| > 0.005 → رفض برسالة تُظهر الرقمين.
   المحسوب حسب الجهة (stage-2b §2.3): كشفهم = افتتاحي + Σمدين − Σدائن،
   وكشفنا = افتتاحي + Σدائن − Σمدين (أونكس: رصيد المورد دائن) — أي: افتتاحي + Σ الموقَّع.
3. `announcedCount` إن ورد ويختلف عن عدد البنود → رفض.

**201**: `{statementId, lineCount, totalDebit, totalCredit}`
- الكتابة: معاملة واحدة — `source_files` + `statements` (status `committed` مباشرة،
  فترة الكشف min/max تواريخ البنود، opening/closing) + `statement_lines`.
- `signed_amount`: كشفنا = دائن − مدين، كشفهم = مدين − دائن.
- `extracted_refs`: كل الأرقام 2–6 خانات من البيان+المرجع (dedup) — لتقاطع المطابقة (Module 4).
- تحذير `findOverlapping` يُسجل في سجل الخادم عند تقاطع فترة مع كشف معتمد سابق (نفس الحساب/الجهة/العملة).
- التدقيق: `STATEMENT_COMMIT`.

### POST /statements/manual — إدخال يدوي/OCR (بلا ملف)

`{accountId, side, openingBalance?, lines:[{entryDate, description, ref?, debit?, credit?, ocrConfidence?}]}`
- نفس محقق البنود. `ocrConfidence < 0.9` في أي بند → `needs_review=true` على الكشف كله.
- **201**: `{statementId, lineCount}` — تدقيق `STATEMENT_MANUAL`.

### GET /statements/{id} — تفصيل كشف ببنوده (الجميع)

**200**: `{statement:{…, opening_balance, closing_balance, period_start, period_end, status}, lines:[…]}`

## قرارات مسجّلة

- **صرامة التواريخ**: YYYY يقتضي 4 أرقام؛ السنة القصيرة (26→2026) تُقبل فقط في تمريرة
  متساهلة ثانية، وتُقدَّم فيها صيغ «يوم-أولاً» (DD/MM) على «السنة-أولاً» — `30-06-26`
  = 2026-06-30 وليس 2030-06-26. الشهور/الأيام تُدقق (<1990 مرفوض).
- **تنظيف المبالغ**: يُسقط ضوضاء العملة (YER/USD/SAR/ر.ي/﷼/$) وفواصل الآلاف قبل التحويل.
- **سطر الافتتاحي داخل الجدول** (بتاريخ صالح) يبقى بنداً عادياً — لا يُستخرج رصيداً؛
  الاستخراج مخصص لصفوف الترويسة بلا تاريخ.
- الخلايا تُقرأ إما من الأعمدة المضبوطة بالقالب (A,B,C,D,E) أو بالأسماء العربية/الإنجليزية
  الشائعة في صف الترويسة (تاريخ/بيان/مدين/دائن/مرجع…) — الأفضل مع القوالب المحفوظة.

## الواجهة (المعالج)

`StatementUploadStep` متصل بالخادم: رفع فعلي (FormData + قنوات الجلسة الثلاث)،
قوالب الحساب حقيقية (خيار «تلقائي» دائماً)، تصحيح كل خلية يُحفظ في المعاينة الخادمية
(فشل الشبكة يعيد النص السابق)، حقلا «ختامي/عدد معلن» اختياريان في محقق التوثيق،
والاعتماد يستدعي commit ويعرض رقم الكشف. `StepCreateSession` يعرض الموردين الحقيقيين
ويحسب `accountId` من (الطرف + العملة). تبقى عرضية: قائمة الجلسات القائمة (تعارض) وسجل
الجلسات — Module 4/6.
